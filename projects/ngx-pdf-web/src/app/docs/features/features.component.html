Features

Every capability of <ngx-pdf-viewer>, with the exact input, output, or method that drives it. If it isn't on this page, the library doesn't do it — see what it leaves to you at the end.

Rendering

  • Canvas page rendering Real canvas elements in your own DOM — no iframe, no shadow root. Continuous vertical scrolling, with only pages near the viewport drawn and off-screen ones released.
  • Selectable text layer Positioned over the canvas so text can be selected, copied and found. renderText toggles it; renderTextMode can defer to the document's own copy permissions.
  • Annotation layer Link annotations, sticky notes and popups, plus optional interactive form widgets, via annotationMode.
  • HiDPI-correct output Canvases rasterise at devicePixelRatio and are scaled back down in CSS, so pages stay sharp on high-density displays.
  • Fully restyleable layers Nothing is encapsulated — override .textLayer, .annotationLayer and .page from your own global CSS, including search highlight colours.
info
Layer positioning ships automatically The text and annotation layers are positioned by pdf_viewer.css, which the library injects from the CDN on first load — no stylesheet to add. It is inserted at the top of <head>, so your own CSS still wins.

Zoom, fit and rotation

  • Three fit modes zoomScale takes 'page-width', 'page-height' or 'page-fit', measured from the container. 'page-fit' uses whichever axis is more constraining.
  • Zoom multiplier zoom multiplies on top of the fit mode, snapped to 5% increments for predictable steps. Not clamped by the library.
  • Reading position preserved across zoom Changing scale keeps you where you were, including the offset within the page — not just the page number.
  • Natural size originalSize ignores the container and renders at zoom alone.
  • Rotation rotation in degrees, added to each page's intrinsic rotation. Use multiples of 90; the library does not validate it.
  • Automatic re-fit on resize autoresize (on by default) recomputes scale on window and host element resize, debounced 100 ms.
  • Page borders showBorders keeps PDF.js's page borders and reserves their width in the fit calculation.

Navigation

  • Controlled current page Set page to navigate; it is clamped to 1…numPages.
  • Scroll-driven page tracking pageChange emits as the user scrolls, debounced 100 ms. Echoing it straight back into page is the expected pattern and will not fight the scroll.
  • Stick to page stickToPage re-asserts the target page once a programmatic navigation settles.
  • Hand tool enableHandTool gives a grab cursor and drag-to-pan scrolling.
  • Document outline getOutline() and the outlineLoaded output expose the bookmark tree; navigateToOutline(item) jumps to an entry's internal destination.
  • Link handling Internal links navigate within the document. externalLinkTarget chooses how external ones open — 'blank', 'self', 'parent', 'top' or 'none'.

Search

  • Whole-document search search(query, options?) runs through PDF.js's find controller, so matches highlight and scroll into view across the entire document — not only rendered pages.
  • Match navigation findNext(), findPrevious() and clearSearch().
  • Live match count searchResults emits { current, total }, or null when cleared or nothing matched.
  • Search options caseSensitive, entireWord and highlightAll.
terminal component.ts 
readonly viewer = viewChild(PdfViewerComponent);

search(term: string) {
  this.viewer()?.search(term, { caseSensitive: false, entireWord: false, highlightAll: true });
}

Document actions

  • Download download(filename?) saves the original bytes unchanged. Defaults to document.pdf.
  • Print print() prints through a hidden iframe, so output matches the source rather than a re-render.
  • Thumbnails getThumbnail(page) returns { url, width, height } — a PNG data URL capped at 150 px wide.
  • Metadata getMetadata() returns { info, metadata } straight from PDF.js.
  • Page count getPageCount() returns 0 when nothing is loaded — the only one of these that never throws, so it doubles as a readiness guard.
warning
Guard these behind a loaded document download, print, getThumbnail, getMetadata and getOutline reject with PdfViewerError('INVALID_STATE') if called before afterLoadComplete fires.

Loading and lifecycle

  • Lazy initialisation PDF.js is dynamically imported and the viewer is built only once an IntersectionObserver reports the host on screen. Off-screen viewers cost nothing.
  • Flexible sources src accepts a URL string, Uint8Array/ArrayBuffer, a URL, or a full PDF.js parameters object whose options win over the defaults.
  • Source de-duplication Re-assigning the same string or the same Uint8Array reference does not reload the document.
  • Download progress progress emits { loaded, total } while fetching.
  • Custom loading placeholder loadingTemplate takes your own ng-template.
  • Password-protected PDFs passwordProvider is asked for the password; returning null cancels cleanly with PASSWORD_CANCELLED instead of hanging.
  • Typed errors Every failure arrives on the error output as a PdfViewerError with a stable code.
  • SSR safe Browser-only paths are guarded by isSSR(), which is exported so your own code can branch the same way.
  • Render lifecycle events afterLoadComplete, pagesInitialized, pageRendered and textLayerRendered.

Reference tables

Text layer modes

Value Numeric Effect
RenderTextMode.DISABLED 0 No text layer — text cannot be selected or found.
RenderTextMode.ENABLED 1 Text layer always rendered. The default.
RenderTextMode.ENHANCED 2 Renders the text layer only when the document permits copying.

renderText="false" disables the layer regardless of renderTextMode.

Annotation modes

Value Effect
'none' No annotation layer at all.
'enabled' Links, sticky notes and popups. Form fields render flat. The default.
'forms' Also renders interactive form widgets (inputs, checkboxes, selects).
'storage' As forms, plus PDF.js persists entered values in its annotation storage.

Error codes

Code Raised when
INVALID_SOURCE src is empty or not a recognised source shape.
LOAD_FAILED Network, CORS, or a malformed/corrupt PDF.
PASSWORD_REQUIRED Encrypted PDF and no passwordProvider bound.
PASSWORD_CANCELLED The provider returned null or threw.
INVALID_STATE A document method ran before a document finished loading.
RENDER_FAILED PDF.js failed while rasterising or scaling a page.

What this library does not do

It is headless on purpose. The demo's toolbar, search bar and dropdowns are application code built on the API above — they are not part of the package.

  • No toolbar or chrome. No buttons, page field, zoom control or sidebar ship with the component. You build the UI; the viewer renders the document.
  • No annotation or form editing. Existing annotations and widgets render, but PDF.js's annotation editor (drawing, highlighting, free text, signatures) is not enabled.
  • No thumbnail sidebar. getThumbnail(page) gives you the image; laying out a strip is yours.
  • No presentation mode, spread view or horizontal scrolling. Rendering is single-column vertical.
  • No PDF creation or editing. Read-only — download() saves the original bytes unchanged.
  • No bundled CSS for the document. You add pdf_viewer.css yourself, which is what makes the layers restyleable.
